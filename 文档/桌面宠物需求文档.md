# 桌面宠物需求文档（参考稿）

> 目标：给“从 0 开始做一个桌面宠物（桌宠）”提供一份可直接落地的需求参考。本文以 Windows 为优先平台，同时预留 macOS 的可行性。

## 1. 背景与目标

### 1.1 背景
桌面宠物通常以“常驻桌面的小型透明窗口”形式存在，通过形象展示 + 轻交互，为用户提供陪伴感、轻松解压的氛围，以及可选的轻量聊天能力。

### 1.2 产品目标
- 提供一个**稳定、轻量、不打扰**的桌面常驻角色，主打“可爱、幽默、轻松”。
- 交互尽量简单：少设置、少按钮、少打断，让用户“看一眼就会用”。
- 支持“角色人设 + 表情动作联动”，让互动更像“跟一个有性格的小家伙相处”。
- 对话能力以“轻聊天/玩梗/逗趣”为主：
  - 默认可离线运行（内置语料/随机台词）。
  - 可选接入本地模型（如 Ollama）或 OpenAI 兼容接口增强聊天。

### 1.3 设计原则
- 默认不打扰：不做“办公助手式”的强提醒；主动互动默认轻量且可一键关闭。
- 轻松优先：功能宁少勿杂，避免把桌宠做成“专业工具集合”。
- 数据本地优先：配置与对话历史默认存本地用户目录；提供一键清空。
- 可扩展但不外露：底层结构允许扩展，但 UI 不暴露“开发者/专业”概念。

## 2. 范围定义

### 2.1 MVP（必须做）
- 桌宠形象渲染（至少一种：精灵图/动图 或 Live2D）。
- 桌面悬浮窗口：透明、无边框、置顶、拖拽移动、缩放。
- 基础交互（“少而刚好”）：
  - 托盘菜单：显示/隐藏、锁定/解锁、切换角色、设置、退出
  - 右键菜单（可选）：与托盘一致，方便快速操作
  - 开机自启（可选，默认关闭）
- 轻松互动：
  - 点击/摸摸：触发“撒娇/生气/害羞/装死”等趣味反馈
  - 随机碎碎念：不依赖 LLM 的内置幽默台词库（可配置频率/可关闭）
- 简单对话气泡：
  - 默认：离线“台词/反应库”对答（例如彩虹屁、吐槽、冷笑话）
  - 可选：接入 LLM（支持 OpenAI 兼容接口；Ollama 走兼容或专用配置）
- 角色系统：
  - 角色列表、切换角色
  - 每个角色独立的口头禅/台词风格（MVP 可先做“台词包”，不一定上复杂 persona）
- 本地配置：尽量少项（音量/是否说话/频率/置顶/穿透），本地持久化。

### 2.2 V1（建议做）
- 表情/动作联动：基于“情绪状态机”或规则触发表情、动作、嘴型。
- 语音合成 TTS（可选）：桌宠“开口说话”，默认关闭，提供音量/语速/音色。
- 迷你玩法（弱打扰）：
  - 投喂/道具：投喂后有不同反应与短动画
  - 每日彩蛋：每天随机一句“今日份废话/冷笑话”
- 轻量记忆（可选）：只记“昵称、称呼偏好、喜欢的梗”等少量信息；一键清空。

### 2.3 V2（可选高级）
- 主动互动 2.0：在“用户空闲”时做更拟人的互动（依然可一键关闭/静音）。
- 多端角色生态：角色商店/订阅/分享（先做本地导入，再做线上）。
- 若未来一定要加入“屏幕感知/摄像头”等能力：
  - 只做“手动触发”，并给非常清晰的可见提示
  - 不把它作为桌宠卖点（避免变成“监控感”产品）

## 3. 用户与场景

### 3.1 目标用户
- 喜欢桌面陪伴/个性化/可爱风格的普通用户。
- 想在工作/娱乐间隙“被逗一下”的用户（解压、放松）。
- 可选：愿意折腾本地模型（Ollama）让桌宠更会聊天的用户（但不是主目标）。

### 3.2 核心场景
- S1：用户打开电脑，桌宠常驻并保持上次位置与大小。
- S2：用户无聊时点一下桌宠，它给出一个可爱/吐槽/冷笑话式的反馈。
- S3：用户拖动/缩放桌宠到合适位置，锁定后减少误触，安心常驻。
- S4：用户切换角色后，台词风格、动作表情随角色改变。
- S5（可选）：用户开启“说话模式”（TTS），桌宠用短句播报，同时做嘴型。

## 4. 功能需求

### 4.1 桌宠窗口与交互
- 透明无边框窗口，默认置顶（可设置关闭置顶）。
- 支持点击穿透：
  - `跟随鼠标`：鼠标悬停桌宠区域可交互，否则穿透。
  - `完全穿透`：适用于纯观赏模式。
- 支持拖拽移动（按住某区域/快捷键临时关闭穿透）。
- 缩放：
  - 鼠标滚轮缩放（可开关）。
  - 设置面板缩放滑条（含最小/最大值，如 0.5 ~ 2.0）。
- 位置锁定：锁定后不可拖拽，且默认开启点击穿透以免误触。
- 托盘菜单/右键菜单：
  - 显示/隐藏
  - 锁定/解锁
  - 打开设置
  - 切换角色
  - 退出
- 开机自启（Windows 以注册表/快捷方式方案；macOS 以登录项方案）。

### 4.2 角色与资源系统
- 角色类型：
  - Live2D 模型（Cubism 4 Web）
  - 精灵图（spritesheet）/GIF/WebP（动图）
  - 静态图片（PNG/SVG）作为简化模式
- 角色资源目录结构建议：
  - `pets/<petId>/pet.json`（元数据：名字、类型、资源路径、默认动作/表情映射）
  - `pets/<petId>/assets/*`（模型文件/纹理/动图等）
- 角色切换：
  - 切换时尽量无闪烁；保留窗口位置与缩放。
  - 每个角色可有独立 UI 配置（比如气泡位置）。
- 资源导入：
  - 支持“导入宠物包”（zip），导入后拷贝到用户数据目录。
  - 导入时做校验：文件结构、大小限制、潜在风险文件（如可执行脚本）拒绝。

### 4.3 对话与气泡
- 对话入口：
  - 点击桌宠某区域触发
  - 托盘菜单打开
  - 全局快捷键（可选）
-- 气泡呈现：
  - 离线模式：立即返回短句（更像吐槽/俏皮话）。
  - LLM 模式：支持流式逐字输出（可选）。
  - 气泡位置可拖拽、可设置跟随桌宠某锚点（左上/右上/左下/右下）。
  - 文本渲染以“易读”为主：支持换行、表情符号、简单强调；不强调代码/表格等专业内容。
- 对话控制：
  - 一键暂停/继续输出（中断流式请求）。
  - 一键清空当前对话。
  - 复制本次回复。
- 多会话（可选）：
  - 最近 N 个会话列表
  - 按角色隔离会话

### 4.4 LLM 接入（多 Provider）
- Provider 类型：
  - OpenAI 兼容（baseURL + apiKey + model）
  - 本地 Ollama（同样通过 OpenAI 兼容或专用配置）
- 必须支持：
  - 超时与重试（可配置）
  - 请求取消
  - （可选）流式输出
- Prompt 结构建议：
  - `system`：角色人设 + 安全/隐私约束
  - `developer`（可选）：产品规则（比如情绪标签格式、短句要求、幽默风格）
  - `user`：用户输入（不引入截屏/摄像头等重感知作为主路径）
- 角色人设：
  - 每个角色一套 `system_prompt`
  - 支持“说话风格模板”（例如“短句、口语、2-3 句内”）

### 4.5 表情/动作联动
- 输入信号：
  - 规则：关键词/情绪词匹配
  - 协议：模型回复末尾输出 `[emotion: happy|sad|angry|surprised]`
  - （可选）结构化 JSON：`{"emotion":"happy","action":"wave"}`
- 执行策略：
  - 优先播放表情（expression），其次动作（motion），再退化到简单抖动/缩放动画。
  - 防抖：同类动作短时间内不重复触发。
- 可配置映射：
  - 每个角色可配置 emotion→表情/动作列表

### 4.6 语音（可选）
- ASR（语音转文字）：
  - MVP 可先做“按住说话/点击录音”
  - 可选离线（如 Vosk / Whisper 本地）与在线（如厂商 API）
- TTS（文字转语音）：
  - 至少一种引擎可用
  - 支持开关、音量、语速、音色
- 口型同步：
  - 基于音频能量驱动嘴型（简化版）
  - 或 Live2D 参数驱动（如 MouthOpenY）

### 4.7 记忆（可选）
- 记忆分层：
  - 短期上下文：最近 N 轮原文
  - 长期摘要：达到阈值后自动摘要
- 结构化事实：如用户昵称、喜欢被怎么称呼、偏好的梗/禁忌词
- 记忆管理：
  - 导出/导入
  - 清空
  - 单角色隔离（建议）

### 4.8 主动互动（可选）
> 默认关闭；开启后也必须“轻量、不打扰”，并支持一键静音/暂停。

- 定时器：间隔范围（min/max 随机），并提供“工作模式”（完全不主动说话）。
- 内容风格：只允许短句（1-2 句），以玩笑/关心/鼓励为主，不输出长篇建议。
- 触发策略（不做屏幕监控版本）：
  - 仅基于时间 + 用户操作（例如“用户点击过桌宠后的一段时间内更活跃”）
  - 不引入截屏/摄像头作为默认能力

## 5. 配置与数据

### 5.1 本地数据目录
建议使用系统用户数据目录（例如 Electron 的 `userData`）存储：
- `config.json`（运行配置：provider、UI、开关）
- `pets/`（用户导入的资源）
- `profiles/`（角色人设与独立配置）
- `memory/`（记忆文件，可按角色分）
- `logs/`（日志，尽量只记录运行状态，不记录敏感内容）

### 5.2 配置项（示例）
- LLM（可选）：`api_base`、`api_key`、`model`、`temperature`、`system_prompt`
- UI：主题色、字号、气泡开关、气泡位置、缩放
- 语音（可选）：TTS provider、音色、音量
- 主动互动（可选）：频率、静音、工作模式

## 6. 非功能需求

### 6.1 性能
- 常驻 CPU 占用：空闲时尽量接近 0（允许少量渲染开销）。
- 内存占用：目标 < 300MB（取决于 Live2D 纹理与模型大小，需监控与优化）。
- 渲染帧率：默认 30fps，提供 60fps 开关（高耗电提示）。

### 6.2 稳定性
- LLM 请求失败要可恢复（提示重试、降级为离线模式）。
- 资源缺失/损坏要有兜底：提示用户重新导入/切换到默认角色。

### 6.3 隐私与权限（强制）
- 不做“强感知桌宠”作为默认形态；如未来加入截屏/摄像头等能力：
  - 必须默认关闭
  - UI 明确开关与状态指示
  - 触发时提供强可见提示（例如“正在截屏/正在使用摄像头”）
- API Key 保护：
  - 不写入日志
  - 支持“仅本地保存/不保存（每次启动输入）”

### 6.4 跨平台
- MVP：Windows
- V1：尽量支持 macOS（至少可构建、可运行、基础功能可用）
- 平台差异点：
  - 开机自启实现不同
  - 读屏/OCR/窗口管理 API 不同
  - 摄像头权限弹窗与签名要求不同

## 7. 技术建议（非强制）
- Electron + 前端框架（React/Vue/Svelte 任一）+ 渲染引擎：
  - Live2D：PixiJS + live2d runtime（或官方 web sdk）
  - 图片/动图：Canvas/WebGL/DOM 任一
- 分层建议：
  - 主进程：窗口、托盘、系统能力、文件与权限、截屏/摄像头采集
  - 渲染进程：宠物渲染、气泡 UI、设置 UI
  - services：LLM、TTS、记忆、工具调用
  - shared：类型、协议、配置结构

## 8. 里程碑（建议）
- M0（1-2 周）：桌宠窗口 + 角色渲染（静态/动图）+ 托盘 + 基础设置
- M1（2-4 周）：轻松互动（摸摸/点击反馈）+ 台词库对答 + 动作表情系统
- M2（4-6 周）：Live2D（可选）+ 资源导入（宠物包/台词包）
- M3（6-8 周）：TTS（可选）+ 轻量记忆（可选）+ 小玩法（投喂/彩蛋）
- M4（可选）：更自然的主动互动（不依赖屏幕监控版本）

## 9. 风险与注意事项
- Live2D 相关授权：模型素材与部分核心运行库可能有商用限制，发布前必须确认授权范围。
- 安全与隐私：截屏/摄像头/工具调用极易引发信任问题，默认关闭并做好透明提示与审计。
- 资源体积：模型纹理与语音模型可能很大，需提供“轻量包/全量包”策略。
